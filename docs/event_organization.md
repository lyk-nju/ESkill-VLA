# Event Organization：用有意义的事件组织监督

本页维护 Event 的定义、设计理由与参考来源，服务于 [idea.md](idea.md)。具体样本字段、路径采样和训练约定集中在 [design.md](design.md)。

## 1. 为什么以 Event 为组织单位？

完整任务通常包含多个持续时间不同、具有相对稳定操作目的的片段。将这些结构折叠成逐帧动作标签，会失去可直接利用的行为语义、目标状态与结果对应关系。

Event 当前定义为：**一条臂的一次 Skill 执行所对应、具有相对一致操作意图与任务意义的变长交互区间。** Event 是具体执行实例，Skill 是跨臂复用的操作类型；同一种 Skill 可对应多个不同场景下的 Event。它为本臂的技巧类别、当前交互对象、终点视觉目标和剩余粗运动轨迹提供共同索引；原始同步视频、状态和联合动作仍然保留。

双臂既可能各做各的，也可能共同操作一个物体，因此按臂维护事件流，而不是要求整个机器人在同一时刻只有一个 Event。**同臂事件有序、互不重叠；跨臂事件可并发，结合必要的任务依赖描述整体任务。** 这保留“一个 Event 就是一次 Skill 执行”的出发点，不需枚举左右臂技能组合。

这一组织有助于提出可检验的监督假设，但 Event 边界本身不是创新效果的保证，也不要求推理时调用人工状态机。

## 2. 当前怎么划分与使用？

首轮优先使用可核验的脚本／状态记录辅助语义分段，人工检查边界与标签；自动事件发现不作为开始训练的前提。RoboTwin 生成脚本提供线索，哪些信息已经被数据导出仍需核查。

在共同时间轴的当前时刻 \(t\)，分别关联左右臂的活动 Event \(\mathcal E_{i_L}^L\)、\(\mathcal E_{i_R}^R\)。两者可以有不同技巧、对象和终点 \(t_e^L,t_e^R\)。primitive 的时间重叠证明需要表达并发，不意味着每个 primitive 都应成为独立技能。

技能首先按交互目的定义，不要求拆成最小控制阶段。技巧粒度与边界规则必须一起确定。例如 Pick 可覆盖接近、闭合和抬升；若采用 Approach / Grasp / Transport，需相应细分事件。不能以夹爪闭合直接判定成功抓住，也不能把某个物理瞬间自动当作所有任务的语义边界。

| 时间概念 | 职责 |
| --- | --- |
| Event 区间 | 组织语义、目标与剩余运动标签 |
| 物理关键状态 | 接触、夹爪和对象变化，为边界与结果提供证据 |
| 运动预测时域 | 从当前时刻到事件终点的完整粗空间路径，以固定数量点表达 |
| 动作执行窗口 | 执行短动作块后重新观察，独立于事件长度 |

模型训练从共同时间轴采样，覆盖各臂 Event 内不同阶段。分别构造当前到各自事件结束的剩余空间路径，按各臂归一化弧长采样，而不是始终只从事件起点预测。事件终点采用实际示范记录，不把末端位置强制拉到对象中心。两臂相同空间进度不等于相同未来时间；时间戳保留用于同步，不额外引入剩余时长预测头。

无主动操作的已知区间用 idle；保持抓持／支撑关系用 hold，保留对象；返回规定姿态用 return，无被操作对象时不伪造对象标签。运动静止本身不能区分 idle 与 hold，未知标注空缺也不能直接填 idle。逐臂、逐角色保存监督有效性：当前 ee 可有效而 obj／goal 无定义，缺少某项标签不屏蔽真实动作监督。静止臂的路径按实际记录生成，只有实际路径近零才使用零位移。

## 3. 必须保留哪些关系？

保留全局任务、臂身份、同臂顺序、跨臂时间关系、对象角色、语义标签及来源置信度，并在可获得时记录预期效果、实际结果与进入条件。目标状态和实际结果分开：失败示范的最终画面不应直接冒充期望成功目标。

当两臂共同追求同一物体的同一终态时，记录共享目标组，按共同效果对齐语义终点，使用同一对象身份、目标时间和参照区域。仅标相同 actor ID 不够，否则两臂可能分别学到抬升中途和抬升完成的冲突目标。各自末端路径仍保留真实记录；无法核验共同终态时不虚构有效 goal。handover 等同物体、不同阶段／效果的操作不强行共用终点。该约定用于标签一致性，Stage 1 不另设协作技能头或协作损失。

重复尝试是否属于同一事件取决于所选粒度。即使两次尝试技巧相同，当前状态与后续运动也可能不同，模型需要必要历史；技巧 ID 不能替代任务进展。

先按完整示范划分训练／验证／测试，再生成片段。当前输入不得包含未来事件边界、协作组、真值对象身份、终点图像或真值技能；标签有效性仅用于损失。已知机器人配置中的臂是否存在可用于在线 mask，但存在而静止的臂不属于缺失臂。未来信息只构造训练标签。

## 5. Stage 1 的实施重点

先保证各臂边界、技巧与对象角色一致，检查独立并发、共同操作、idle／hold、短事件与交接状态能否形成正确标签。保留事件内部各阶段的训练样本，避免只有事件起点得到监督。

首轮随完整方案评测平均任务成功率，不把边界、采样和监督的逐项消融作为前置条件。若发现特定阶段训练不足，再调整采样或核查标注。未来跨本体扩展需共享操作语义，不能将某种机器人的夹爪命令作为所有数据来源的唯一事件定义。
