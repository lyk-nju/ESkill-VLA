# RoboTwin 数据构建草案

状态：数据链路讨论；2026-10-30。已确定 π0.5、仿真优先、借鉴 GuidedVLA 的数据与训练方法。RoboTwin 是与现有双臂设计相符的候选；任务、规模、采集条件和补标实现仍待确定。本文不启动新采集、模型补标或训练。

2026-10-30 最新决定：原生实例区域与完整夹爪框试点后，用户选择 RoboTwin 直接使用原生 bbox／mask，**不接外部视觉定位／分割模型**。后文较早的 VLM＋SAM 补标讨论保留为历史；不作为当前 RoboTwin 流程。当前缺口与工程收尾以 [原生字段自查](check/native_field_check.md) 为准。

## 借鉴的方法与本项目的标签

GuidedVLA 使用“阶段划分 → Qwen3-VL 提供对象提示／技能候选 → SAM2 跟踪区域 → 人工核验”，并把像素 mask 转成 patch 标签；其 LIBERO 训练先做纯动作微调，再继续加入辅助监督。来源：[论文 III-D、附录 I／J](https://arxiv.org/html/2605.12369v2)。我们借鉴构建顺序和核验方法，训练目标仍遵循 [Design](../../docs/design.md)。

| 构建内容 | RoboTwin 候选做法 | 需要核验 |
| --- | --- | --- |
| 原始示范 | 保存同步 RGB、双臂状态／动作、末端位姿、任务文本和时间轴 | 控制语义、15 Hz 来源频率、末端参考点及坐标 |
| 每臂 Event | 用户已确认以原语区间为骨架，轻量映射、相邻合并及有证据的 Hold／Idle 补段；保留双臂并发 | 默认保留源边界，语义冲突／同步等待才有依据地修正；规则见 event_plan.md |
| 技能标签 | 每臂 Event 对应共享词表，展开为逐帧当前技能 | 不照搬 GuidedVLA 三类阶段或窗口直方图；未知不补为 idle |
| 当前执行器区域 | 使用原生 link 区域；辅助无外部遮挡渲染生成屏内完整夹爪框 | 保留 visible／full 定义；旧 HDF5 没有区域标签，不能凭空补齐 |
| 当前对象区域 | 使用原生实例 ID、逐对象区域；语义 annotation 决定当前臂操作哪个对象 | 搬运阶段不能切换为容器／目的地；多 link 对象已可合并 |
| 事件终点对象区域 | 取同一对象在本臂 Event 终点的 RGB 和区域 | 终点可观测、时间对齐；共享协作终态按 Design 对齐 |
| 剩余三维路径 | 读取本臂当前至事件终点的真实末端位置，再按弧长采样 | 保留物理尺度与两臂共同坐标；不能用物体中心替代末端 |
| 训练样本 | 当前／历史输入配合动作块和上述辅助目标；先按完整轨迹拆分 | 真值区域、未来图像、终点及 actor ID 只用于标签，不进入在线输入 |

保留像素区域或足够精细的原始标注，再生成模型所需的画布／网格目标。GuidedVLA 发布的 16×16 patch mask 不能当作精确像素分割，也不宜成为本项目唯一保存的区域版本。

## 已有证据与主要缺口

2026-10-30 补充确认：图像补标后续采用 **VLM＋SAM3** 作为拟验证方案。VLM 负责夹爪／操作物体的任务角色与实例选择、描述及必要的位置提示，SAM3 负责分割和视频跟踪；子事件整理参考 AtomSkill，继续利用脚本和状态证据。RoboTwin 还需核验左右臂身份、交接时同一对象关联及 Hold，不能用图像左右位置替代臂身份。新采集若有可靠原生实例分割则复用；旧数据缺失区域可用这条图像补标链补充。具体模型、预算与试点协议未确定，尚未启动补标，不将该方向写成已验证的效果提升。

- 现有 HDF5 使用 `state = 原序列[:-1]`、`action = 原序列[1:]`；关节 action 来自下一采样时刻的记录，不自动等于专家原始指令。适配 π0.5 时单独明确目标、delta 转换及夹爪语义，不能照抄 LIBERO 动作变换。依据：[转换器](../../../RoboTwin/envs/utils/pkl2hdf5.py)。
- 10 条读取样本都缺少最后一帧 HDF5 RGB，但原视频容器报告保留完整帧数。先核验原视频画面与 HDF5 相机的对应及逐帧映射；未核验前不能直接拿最后一帧视频替代，也不能把事件终点夹到倒数帧。
- 现有 `subtasks` 有 `arm/start_frame/end_frame/actor`，但部分 lift／retreat 的 actor 为空；需要依据可核验的抓持关系追踪对象，不能仅向前填充最近对象。源区间的结束索引需明确转换到项目 Event 约定。
- 源记录存在 contact／grasp／release 等事件，但不等于已验证的持续抓持。特别是交接期间另一臂的 hold，需结合对象关系、夹爪及实际画面核验，不能按静止判断。全局稀疏 `frame_labels` 也不能代替完整按臂事件流。
- 仿真分割接口会把 ID 转为 uint8／伪彩色；若选用原生分割，需保留原始 ID 和 actor／link 映射。旧数据缺少这些标签，能否可靠重放恢复尚未验证。依据：[分割接口](../../../RoboTwin/envs/camera/camera.py)。

## 接下来的顺序

1. 核对现有 10 条轨迹：同步、对象关系、双臂并发和终点画面；核验视频放 `check/`，人工结论单独记录。
2. 讨论技能粒度及关键缺口的补充途径。需要新采集、仿真重放或模型补标时，先写具体试点方案，确定样本、预算和可视化后再实施。
3. 在标签可用性明确后，确定首批任务、clean／randomized、示范量和按轨迹的拆分，生成 π0.5 训练适配与统计。归一化统计只用训练集；动作块与辅助标签可各自屏蔽缺失项。

训练参考以“π0.5 初始化 → 同源示范适配 → ESkill-VLA 联合训练”为候选组织方式；是否单独设置纯动作预微调阶段、动作窗口、优化器、步数及损失权重，需结合本项目与预算确定。GuidedVLA 的注意力损失权重不能直接用于我们的视觉去噪和三维路径损失。

## 新版文件结构与职责规划

2026-10-30，按用户要求制定并随后实施代码重构。以下保留设计依据，实际目录、入口及验证范围以 [README](README.md#重构后的使用入口) 为准。未迁移旧产物或启动新采集／补标实验；Event 规则、补标算法及训练任务仍待核验。架构问题的历史证据见 [architecture_review.md](architecture_review.md)。

### 1. 项目侧：一个来源目录、五个处理文件

```text
ESkill-VLA/data/robotwin/
├── README.md                 # 唯一使用入口：环境、命令、数据位置、当前进度
├── construction_plan.md      # 本规划，后续直接更新，不另建多份版本方案
├── config.yaml               # 该来源处理配置；实现时才创建
├── scripts/
│   ├── source.py             # 读取原始数据、解释源字段和时间映射
│   ├── annotate.py           # 生成每臂 Event、技能与视觉区域
│   ├── render.py             # 视频画面、叠加层与编码
│   ├── check.py              # 字段核对、固定抽样、技术检查、调用渲染
│   └── export.py             # 固定来源清单 → π0.5 基础数据及辅助标注
└── check/
    ├── README.md             # 核验范围、图例、人工判断规则
    ├── field_check.md        # 我们需要什么／有没有／备注
    ├── raw/                  # 原始数据核验
    │   ├── manifest.json     # 来源、10 条样本、seed、处理配置与版本
    │   ├── report.json       # 技术检查和失败记录
    │   ├── manual_review.csv # 人工结论，初始为待核验
    │   └── video/
    └── annotated/            # 新标注核验；首次确有标注后再创建
        └── …                # 与 raw 相同；可比较时使用同一批样本
```

图中省略已有调研文档、证据与历史结果，它们保留原址和链接，不立即删除／搬动。五个处理文件按实际开发顺序出现，不预先创建空文件。`source.py` 是内部模块，其余文件提供各自命令入口；不另加总 CLI、服务层、注册器或通用基类。

| 文件 | 负责的工作与输出 | 边界 |
| --- | --- | --- |
| `source.py` | 列举／读取指定版本 episode；读取 RGB、任务、实测状态、控制记录、末端与源事件；提供源帧／时间对应。用普通函数，必要时用一个小型 episode 数据类 | 不补标签、不渲染、不推断缺失帧。旧数据与新采集格式显式选择，不猜格式；旧驱动目标不伪装成实测关节状态 |
| `annotate.py` | 从源证据生成独立的左右臂 Event、技能、对象关联及每视角执行器／对象区域；输出逐 episode 标注及规则版本 | 不导入仿真环境、不训练模型；只实现已确认的方法。bbox／mask 缺失就保留缺失，不默认触发 SAM／YOLO。对象关联只服务同一对象追踪，不额外扩张模型输入需求 |
| `render.py` | 接收已读取的 episode 与可选标注，按源帧率绘制 RGB、区域、事件与末端路径；输出核验视频 | 不重新判断事件或偷偷补标签；不依赖 SAPIEN、LeRobot、π0.5；原始和补标模式共用布局 |
| `check.py` | `fields` 核对字段，`sample` 固定抽样清单，`render` 调用渲染并检查产物，`validate` 检查选定数据；写报告和待填人工表 | 不修改原始数据、不自动填写人工通过；一份样本清单用于检查与视频，避免重新抽样导致错配 |
| `export.py` | 按固定 episode／split 清单导出基础 RGB、状态、动作；同时保存辅助标注和源 episode／帧映射，记录转换版本与失败 | 复用 XPolicyLab／LeRobot 写入能力，不复制完整转换器；仅基础 LeRobot 文件可用不代表 ESkill-VLA 辅助监督已可训练 |

`config.yaml` 只保存处理参数：来源路径与格式版本、标注输出位置、已选规则及阈值、核验样本量／seed／视角、导出位置与动作映射选择。不复制 RoboTwin 场景配置，不覆盖源数据 fps，不塞入模型优化器和训练超参数。实际运行在 manifest 中保存生效配置和代码版本；代码有未提交改动时记录这一事实及对应差异，不能只记录 HEAD。

### 2. 采集侧：复用原有位置，收窄职责

不再建立第二套 RoboTwin 采集包。保留下列文件并在实施时调整内部职责：

| RoboTwin 文件 | 新职责 |
| --- | --- |
| `scripts/collect_event_dataset.py` | 批量入口：任务／GPU 调度、任务锁、进程退出和结果记录；不负责视频修复、技能解释或导出 |
| `scripts/collect_data.py` | 单任务执行：初始化环境、执行示范、提交原始 episode；也是批量入口调用的 worker |
| `scripts/collection_paths.py` | 唯一的采集路径与原始完成标记助手；派生视频不进入原始完成条件 |
| `envs/_base_task.py` | 在明确采样时刻取得观察与记录；不调用项目标注或核验渲染 |
| `envs/utils/event_recorder.py` | 保存 primitive 区间及可取得的分臂接触／对象等证据；语义合并和展示 NMS 移出采集链路 |
| `envs/utils/pkl2hdf5.py` | 将完整源时间线落盘，保留终点各视角和状态／命令的区别；不提前执行训练样本移位 |

HDF5 是新采集的原始容器候选，不要求必须另外保存一份全部相机 MP4。临时 PKL 可沿用现有实现，完成持久化核验后清理。接触／对象位姿／分割证据的具体采样内容与存储预算在采集试点中确定，不能只记录最终 grasp 标签却期待以后任意重标。

单任务原生入口和批量调度入口各有用途，不机械地合成大文件。新格式必须显式标记；旧数据读取与现有训练入口在迁移期间保留原含义，不静默改变 `state/action` 的解释。

### 3. 依赖方向与环境

```text
RoboTwin 采集进程 ──写入──> 原始文件
                                │
                             source.py
                         ┌──────┼──────┐
                         ↓      ↓      ↓
                    annotate  check   export → XPolicyLab / LeRobot
                         │      │       ↑
                         ↓      ↓       │
                       标注    render   标注 + 固定 split 清单
```

`check.py` 调用 `source.py` 和 `render.py`；`render.py` 接收数据，不反向导入 `check.py`。标注和导出都可以直接读来源，不经核验视频；`export.py` 可复用 `check.py` 的纯验证函数，`check.py` 不导入导出器。模块 import 时不解析参数、不启动任务。采用一种固定的脚本运行方式，避免每个文件重复堆叠 import fallback。

- **采集环境**：RoboTwin／SAPIEN 及其原生依赖。
- **离线处理**：NumPy、h5py、PyYAML、单一 OpenCV 包及所选视频库；RoboTwin HDF5 图像严格复用 `XPolicyLab.utils.process_data.decode_image_bit`，RGB 通道规则不变。该共享工具的导入不应牵出 policy 模块。
- **导出与训练环境**：已有 π0.5／LeRobot 环境。只有 `export.py` 导入 LeRobot，检查／渲染不必安装它。离线处理可直接复用此环境，不强制增加第三套环境。

两个现有环境有不同 Torch 要求，不合并依赖清单。可选模型补标在方法确定后再增加依赖，不提前安装 Qwen／SAM／YOLO。LIBERO 以后采用对应的 `source.py` 等职责，保留单臂与动作语义差异；先不建立跨来源公共框架，出现实际重复再抽取小函数。

### 4. 大数据与导出产物

新增数据放 `/data1/yuankai/robot-research/data/robotwin/<数据集名>/`，与历史 `event_data/` 分开；以下仅为布局规划，不创建目录：

```text
<数据集名>/
├── manifest.json              # 来源配置、代码／资产版本、episode 索引
├── raw/<task>/<episode>.hdf5  # 完整原始记录
├── annotations/<标注版本>/   # 每 episode 的 Event／区域及生成记录
└── training/<导出名>/
    ├── manifest.json          # 固定来源、episode split、源帧映射和失败信息
    ├── lerobot/               # RGB／状态／动作等基础训练数据
    └── annotations/           # 同批样本的辅助标注快照及映射
```

已有采集器的路径习惯可由 `collection_paths.py` 统一映射到新布局，不改写历史目录。原始文件最后原子提交，并包含最少的采集身份／完成信息；manifest 负责运行级索引，不另造多套内容相同的 done 文件。标注 JSON 与大体积 mask 是否分文件依据体积选择，不把存储编码现在冻结成全项目 schema。

导出层保存基础训练数据与源帧映射，训练侧按映射取 Event、当前及终点同对象区域、剩余末端路径，再构造窗口／归一化／模型目标；不逐帧复制未来 RGB 和全段路径。π0.5 训练数据读取器需要明确接入这些辅助标注，现有共享转换器不会自动消费它们。优先复用其写入函数；如当前只有命令入口，先在原文件抽出小函数，不复制整份实现。

训练集按 episode 拆分，归一化只用训练集；导出失败列表必须显式保留，不能静默换样本凑数量。10 条人工核验用于评估来源与规则，不等于全部训练 episode 已人工通过。实际训练准入条件随训练协议单独确定。

### 5. 旧文件去向与实施顺序

| 当前文件／逻辑 | 计划处理 |
| --- | --- |
| ESkill-VLA `scripts/inspect_source.py` | 读取逻辑并入 `source.py`，检查与抽样并入 `check.py`；新入口核对一致后再移除旧入口 |
| RoboTwin `collect_event_samples.py` | 样本采集通过批量入口选择任务与数量；检查调用方后退役重复入口 |
| RoboTwin `render_event_labels.py`／`event_visualizer.py` | 布局迁入项目侧 `render.py`，解除 `envs` 的重依赖；历史入口存在调用方时才保留薄兼容封装 |
| RoboTwin `build_event_review.py`／`summarize_event_samples.py` | 本项目的检查与人工表生成合并至 `check.py`；已有上游用途不未经核对就删除 |
| XPolicyLab 共享转换器 | 保留；供项目 `export.py` 复用基础写入，显式支持新源布局，不假定旧 loader 能直接读取 |
| Pi_05 旧 `process_data.py` | 新管线不使用；先核对调用链再决定是否调整原命令，不维护两套动作转换 |

实施顺序：先整理 `source.py`／`check.py`／`render.py`，利用已有样本核验读取一致性；再收窄原始采集和调度职责；随后按确认的语义实现 `annotate.py`；最后接入 `export.py` 与训练读取器。涉及新采集、重放或模型补标时另按工作区实验规则确认具体试点。

保留的防护只有必要的字段／维度／有限值／时间检查、源映射、原子提交及采集锁。失败在 episode 边界集中记录；必需证据缺失直接报错，可选标签缺失保持 unknown。删除静默猜格式、把异常转成有效标签、确定性错误反复重试和缺一张派生图就重采原始数据等逻辑。目录只在真正产生对应数据时创建。
