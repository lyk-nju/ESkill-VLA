# 八任务 Event：原语骨架与语义整理

状态：用户已确认“以原语为骨架、轻量映射／合并／补 Hold”的原则；具体任务规则、词表和边界修正仍待核验。本轮同步方案文档，未修改采集／标注逻辑，未启动重采或实验。依据当前 [Event](../../docs/event_organization.md)、[Atomic Skill](../../docs/history/atomic_skill.md) 与 [Design](../../docs/design.md)，以及八任务本地 `play_once()`／`check_success()` 源码。2026-10-30。

后续已按单独确认的 [六任务预览协议](../../../workspace/experiment/robotwin_primitive_event_preview/README.md)实施候选映射与视频：909 帧、25 个候选 Event，技术检查通过，人工语义验收待完成。前文草案记录的是提出方案时的状态；当前候选结果见 [视频入口](test/events/README.md)，尚未冻结为正式训练标签。

RoboTwin 专家脚本已按 grasp_actor／place_actor／move_by_displacement 等组合原语组织，内部再执行 move／open／close，并支持双臂并发；已有采集记录把调用过程保存为带 arm／actor／起止帧的 primitive 区间。**直接复用这些原语区间作为 Event 骨架，默认保留已有边界，以少量映射、相邻合并和等待段补充形成项目标签。** 状态用于验证效果、确认对象关系及修正有明确问题的边界，不另从零建立全视频事件发现流程。

Event 仍对应本臂相对一致的交互目的；同臂有序且不重叠，双臂允许不同技能并发。原始 primitive／phase 完整保留；派生 Event 回链到组成它的源记录，明确何处改名、合并或补段，语义标签不覆盖源证据。

## 已确认的整理方式

| 处理 | 典型例子 | 边界处理 |
| --- | --- | --- |
| 直接映射 | 常规 grasp_actor → Pick，back_to_origin → Return | 默认沿用源区间，状态与画面核验 |
| 相邻合并 | 抓取＋紧接取起 → Pick；不松手的放罐移动＋随后 open_gripper → Place | 仅合并同臂、同次目的且对象关联可核验的片段，取组成区间的首尾 |
| 按上下文改名 | place_actor(is_open=False) 用于瓶子调姿或锤子工具接触 | 优先保留原区间，仅更正技能；若取起／撤出准备阶段属于前一个 Pick，再有依据地合并 |
| 补等待段 | 另一臂放汉堡期间，本臂继续持薯条 → Hold；无持物的已知等待 → Idle | 以相邻原语区间及按臂状态圈定空档，不用静止或缺标直接推出标签 |
| 有依据地修正 | 双臂 move 等待使某臂 primitive 终点过晚 | 利用已有 phase 与本臂完成／关系证据调整，保留原边界和修正理由；不普遍重切所有边界 |

这确认的是划分路线，不等于已确认下表约 10 类技能或每一条具体合并。先在八任务现有原语上核验，再定稳定的项目词表。

## 候选技能与边界

首版候选约 10 类，按下面任务核验后再定名；不修改当前共享配置或将词表写成定案。

| 候选 Skill | Event 覆盖与结束依据 |
| --- | --- |
| Pick | 从与此次抓取有关的准备／接近，到建立可核验的受控持物状态。紧接的取起／撤出准备姿态可合并进来；不另标 Approach／Grasp／Lift，也不要求没有抬升脚本的任务凭空多一次抬升。夹爪闭合命令本身不足以证明成功 |
| Place | 持物移向目标支撑区域、对准、释放，到对象被目标区域支持且不再由该臂携带。打开夹爪后离开物体的安全撤离一般放下一 Event；具体交界以状态和画面核对 |
| Reposition | 保持对物体的控制，改变位置或姿态，到本次目标位姿／区域；不包含释放。用于调整持物姿态或持物平移，避免将 `is_open=False` 的 place_actor 照抄成 Place |
| Press | 接近作用点、按下、解除按压／脱离接触的一次完整操作；不因内部调用 grasp_actor 就标 Pick |
| ToolContact | 拿着工具接近并接触作用对象，达到可核验的接触目的；初步用于本地锤子任务。若后续轨迹能证明敲击速度／冲击效果，再评估是否采用 Strike 名称 |
| Pour | 从持容器进入倾倒过程，到内容物转移的效果可核验；同一目的下的连续倾斜／抖动合并，等待内容物下落也属于该目的尚未完成的区间 |
| Release | 从解除控制到对象不再由本臂抓持，未必稳定放到支撑面。用于扑克牌等未核实支撑条件的释放，避免直接等同 Place |
| Hold | 明确维持已建立的抓持／支撑关系，等待另一事件或下一项主动操作；允许维持关系所需的小调整，不能仅按速度近零判断 |
| Return | 无被操作对象时撤离到规定安全姿态或初始姿态；可合并相关撤离与返位片段。单纯世界 z 方向向上不自动标 Lift |
| Idle | 已知无主动交互、无持物／支撑关系的等待；未知／缺失证据保持无效标签，不能默认补 Idle |

以上是连续片段标签。接触、闭合、目标进入、释放等瞬时证据仍另存，用来定位／核验边界，不能将一个接触点拆成单帧技能。

## 八任务的候选划分

| 任务（用户名称） | 建议主事件 | 对象及注意点 |

| beat_hammer_block（本地 beat_block_hammer） | 主动臂：Pick → ToolContact；另一臂：Idle | 操作对象为锤子，方块为作用目标／参照物。源码仅检查接触与平面位置，没有完整敲击循环或冲击判定，首版不强写 Place 或已验证的 Strike |
| click_bell | 主动臂：Press；另一臂：Idle | 把接近、按压和脱离接触连成一次 Press；对象为铃铛。额外真正的返位才标 Return，不能把按压准备误标抓取 |

| moving_playingcard_away（本地 move_playingcard_away） | 主动臂：Pick → Reposition → Release；另一臂：Idle | 同一副扑克牌跨三段关联；源码只验证移至侧方且开夹爪，尚未要求稳定支撑，所以先保留 Release；若核验实际是稳定落在目标桌面，再讨论合并后两段为 Place |
| lift_pot | 两臂并发 Pick（抓持＋共同抬起）；确有持续保持才接 Hold | 两臂绑定同一锅及同一协作终态，统一到可核验共同抬升完成的终点，各臂保留自己的真实末端路径；不新增“双臂 Pick”技能类，不按两条 primitive 的独立结束时刻定义矛盾 goal |

对象名只服务实例关联与子事件描述，Skill 原型描述不写具体对象名。当前 obj 与 goal 一直指本 Event 的同一个被操作对象，不在放置过程中改指目的地；Pour／ToolContact 的参照物与内容物记录不增加新的网络角色。

## 具体边界怎样取得

1. 默认起止来自本臂已有 primitive 区间；若按已核验规则合并同次操作，以组成原语的首尾确定 Event。保留源区间的闭开定义与源终点，不将 stop_frame 与 goal_frame 机械混同。
2. 用受控抓持、放置支撑、按压／工具接触、内容物转移等检查该 Event 的意图与结果。状态首先用于核验；仅在语义冲突、同步等待或有明确完成证据的情况下修正边界，并记录来源与理由。暂不另设跨任务统一的“6 cm 即完成”或“开夹爪即成功”规则。
3. “对象归谁持有／支撑”按臂接触、命令与对象／末端相对运动及视频共同判断。持物等待标 Hold；不持物的已知等待标 Idle；对象掉落、抓取失败或证据缺失另标结果／有效性，不能靠前向填充永久认定 Hold。
4. 同臂按 `[start,end)` 组织，`end` 同时指向该 Event 的终点状态帧；各臂独立，不做旧版跨臂全局 1 秒边界抑制。同步 move 调用造成的统一 primitive 终点不能代替本臂真实完成时刻。
5. 没有独立等待／返位就不增加零时长 Hold／Return。重复动作先按本轮目的和尝试关系判断，不按循环次数机械切 Event。
6. 失败实例保留其意图标签与失败结果；真实失败终态不当作成功 goal。无对象 Return／Idle 的 obj／goal 无效，但 ee 与有效动作监督可以继续使用。细节沿用 Design，不新增学习分支。

## 采集侧目前影响划分的缺口

`dump_bin_bigbin` 的倾倒／抖动直接通过 Action 列表组织，现有 source_evidence 没有 Pour 原语区间。这里需要给这段脚本补最少量的源阶段／对象标记，再合并其连续调用；不能假定所有任务片段目前都有完整 primitive 元数据，也不需要因此引入全视频自动分段。

只读检查发现 `dump_bin_bigbin` 末尾调用 `delay(6)`，其默认 `save_freq=None` 不保存等待中间帧；现有 randomized seed 0、1 在末尾均跨越 **7.20000034 s** 仿真时间。`delay(6)` 不是可靠的“6 秒视频”。目前无法从这两帧之间精确切出倾倒完成与后续 Hold，也不能用插值伪造记录。候选 Pour 可先覆盖至最后可观察结果帧并标边界待核验；后续采集需连续保存延时阶段的 RGB／状态／对象与接触证据，再确定细分。

旧 `get_ee_pose` 参考点、观测—动作对应及真实时间映射按 [字段自查](check/native_field_check.md)统一。当前真实接触和稳定关系只是证据；不把旧事件点自动提升为成功真值。

## 实现思路与下一步讨论

维持“原语与源证据记录 → 离线语义整理 → 标签校验与时间轴渲染”的职责划分。采集器保留原语、phase、arm、actor 与真实时刻，少数未记录的 Action 片段补源标记；映射、相邻合并、对象关联和 Hold／Idle 补段集中在现有 RoboTwin annotate 层，用少量任务规则实现。renderer 只读取已生成标签，左右两条时间轴与原生框同画面展示，不在渲染时重新推断技能。共享 Qwen 文本候选入口可保留其它来源用途，不要求成为 RoboTwin 原语映射的前置步骤。

下一步可按本原则形成具体映射和样例核验协议，再产出左右臂候选时间轴；只显示已标注画面。原则确认不等于已运行或验收候选标签，本轮未启动新采集、模型标注或可视化试验。
