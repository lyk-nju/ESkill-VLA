## 原工作做了什么

监督包含有序子任务列表 task sketch，却不提供逐帧对齐。动态规划边缘化可能的对齐；子策略的动作和停止概率参与联合似然，使控制学习和时间划分互相约束。测试时可以提供新的 sketch。给定程序组合与从自由语言自动发现程序是不同能力。

## 对 atomic skill / target grounding / action representation 的意义与边界

TACO 提供了“硬脚本边界”与“完全无监督分段”之间的重要选择：顺序级语义监督。我们未必需要先得到精确的 Event 区间再训练 atomic skill，也可以让动作证据帮助确定哪个片段属于哪个已知技能。

对 RoboTwin，这可能降低边界工程成本：任务脚本较容易提供 pick→move→place 等有序语义，但控制阶段与接触状态的精确切换可能存在模糊区间。不过，模板的过粗或错误顺序同样会约束模型，必须抽样审查。

TACO 的 stop 概率是原方法用于对齐和执行的接口选择，不意味着本项目必须增加外部完成检测器；Event 是数据组织层，部署切换策略需要单独比较。

## 可以区分机制的实验

使用同一技能字典、同一动作策略和同一训练轨迹，比较精确边界标签、只有有序 sketch、没有技能标签三种条件。分开记录人工/脚本标注成本、边界误差、在线技能选择和闭环组合成功率。

加入连续重复同技能但不同目标的任务，检查 sketch 中的实例身份与 target grounding 绑定是否被混淆。若顺序监督能达到精确边界的控制表现，则首版无需把分段器复杂度当成主要贡献；若精确边界明显更好，再定位优势来自语义还是动作对齐。

## 下一步精读

检查长度不均衡、重复技能与错误 sketch 的处理；确认训练时边缘化对齐与推理时技能执行的差异，以及新的组合是否仍依赖给定 sketch。
