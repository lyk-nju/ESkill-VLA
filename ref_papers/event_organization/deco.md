# DeCo：完整交互、关键帧与技能衔接

> **当前定位（2026-10-28）：核心 · 边界依据。** 追踪 AtomSkill 的物理候选边界与完整交互划分来源。 以 [当前清单](../catalog.json) 与 [方法文档](../../docs/event_organization.md) 为准。

> 以下保留此前原文阅读与推论；其中“核心／优先实现／本轮”等表述属于记录时的判断，不替代上述当前定位。

**论文**：DeCo: Task Decomposition and Skill Composition for Zero-Shot Generalization in Long-Horizon 3D Manipulation；Zixuan Chen 等；arXiv:2505.00527。v1 为 2025-05-01；本轮读 v2（2026-02-15）。[原始记录](https://arxiv.org/abs/2505.00527) · [原文](https://arxiv.org/html/2505.00527v2)。阅读：§II、§III-A–D 及参考[43]，未复现。

**为何补入核心。** AtomSkill §III-A 在夹爪分段处明确沿用本作。DeCo 又在 §III-B 引 Q-attention 的关键帧发现；这条链让边界策略的来源和改变可核查。

**原方法的必要事实。** DeCo 以完整夹爪交互组织 atomic tasks，使用关键帧/目标位姿训练低层策略；VLM 调度已学任务，位姿判断及空间衔接帮助串接。关键帧与完整交互并非同一层级。

**对项目的判断。** 先定义进入条件和结束效果，再讨论一个区间是否应叫原子技能。看上去很自然的语言分解可能留下低层从未见过的后继初态；若仅把每段统一改为新语言标签，无法解释组合执行中的跳变与失败。

最小对照应保持执行器与示范不变，比较单次抓放变化、完整交互和脚本语义三种粒度；在每段终态重置和连续衔接两种设置下评测。前者测技能本体，后者测连接分布，两者不能合并成一个分段准确率。

**限制。** 夹爪开放度只是接触代理；闭合空夹爪、开爪推物和连续保持抓持的任务需要额外定义。原系统的在线调度与空间衔接也不能全归功于数据分段。下一步应核验自动目标位姿是否在不同起始布局中保持适用。
