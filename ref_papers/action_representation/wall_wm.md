## 已核对的原工作

正文方法核对：§3、§4.2–4.5、§5、§7.2.5、§8。以语义事件对齐文字、视频和动作，配合层次标注及视觉语言/动作双聚类平衡采样。视频塔与动作 DiT 协作，动作分支读取视频特征。Event mode 消费下一事件描述并支持变长执行；Unified mode 仍可执行固定动作块。

## 证据边界

§7.2.5 的比较同时改变 VI-SA 与执行模式，不能单独估计事件边界的因果效果。数据策划、采样、模型和训练规模也共同变化；Task Progress 不能改写为任务成功率。§8 讨论了自有平台优势及固定窗在窄任务中的适用性。

## 对本项目的推论

“以 Event 为学习单位”不能单独承担新意。应直接比较事件数据组织能否在相同监督预算下改善知识复用，以及 atomic skill / target grounding / action representation 是否提供额外可验证的分工。

建议把三个变量拆开：边界来源、事件描述、采样分布。先固定模型与数据总量，对每个因素分别消融，再检验交互。另将训练的事件长度、编码长度和实际执行时长分开记录。

## 后续精读

优先复核事件标签构建与质量审查、事件结束/重规划接口、Unified mode 的梯度路径。复现前确认公开数据与作者自有数据之间的缺口，不能直接照搬总榜数字。

## 2026-10-28：当前方法直接使用的来源

沿用此前对 v2 的核查：§3.3 提供事件对齐的视频／动作序列接口，§5.1 讨论 resolution/length bucketing，§5.2 式 (21) 使用剩余时间标量回归与 Huber 损失，§5.5 区分事件执行和固定动作块模式。

动作目标包含物理三维末端位姿及夹爪信息，不是二维图像路径。本项目只取粗 XYZ 作为辅助监督，另保留真实机器人动作专家；这是简化改造，不能称为复现原动作塔。

我们据此设计剩余时长与变长运动 Token，暂不采用其完整视频生成塔。公开示例显式传入 frames，不能据此声称已核实公开部署代码自动完成“预测时长→分配 Token 数”的全部链路。对应设计见 [Action Representation](../../docs/action_representation.md)。
